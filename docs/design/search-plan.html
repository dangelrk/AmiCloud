Implementierungsplan: Suchfunktion (search / find)

Stand: 2026-07-15 · Markdown-Fassung: search-plan.md · Nur Planung — Umsetzung folgt nach Review.

Context

AmiCloud hat bisher keinen Weg, im Cloud-Baum nach Dateien/Ordnern zu suchen — man kann nur Verzeichnis für Verzeichnis mit ls/Panel navigieren. Diese Änderung ergänzt einen search- (Alias find) Befehl in allen drei Front-Ends (CLI amicloud, amicloud-shell, GUI amicloud-commander), der mit den klassischen Jokern *, ? und AmigaDOS #? nach Datei- oder Ordnernamen sucht.

Zwei per Rückfrage bestätigte Design-Entscheidungen:

  1. Server-seitige Suche — ein neuer api.php?action=search-Endpunkt fragt die files-DB in einem Request ab (blitzschnell, auch bei großen Bäumen), statt clientseitig Verzeichnis für Verzeichnis zu laufen.
  2. Standard-Scope = aktuelles Verzeichnis rekursiv (Shell-cwd bzw. aktives Commander-Panel), mit Option „ganze Cloud ab /".
Damit braucht kein Client-Makefile eine neue Lib: der Server macht das Matching, die Clients rufen nur cmd_search() in libcloudhttp auf. Der existierende changes()-Endpunkt ist die fast wörtliche Vorlage; der Wildcard-Matcher pattern.h (libcloudfs) wird nur im Commander für die lokale Panel-Seite gebraucht.

1. Server: neuer action=search

server/api.php

Neuen case in den Dispatch-switch (nach case 'changes', ~Zeile 35):

case 'search':   FileStore::search($path, trim($_GET['q'] ?? ''),
                     isset($_GET['dirs']) ? (bool)$_GET['dirs'] : true); break;

$path ist der Scope-Root (schon via sanitizePath geholt); q ist das Wildcard-Muster.

server/includes/FileStore.php

Nach changes() (Zeile 501–532) analog aufbauen — dieselbe SELECT-Form, dieselbe Envelope-Struktur (entries-Array mit /-präfixierten Pfaden):

/* Glob (*,?,#?) -> SQL-LIKE. Reihenfolge wichtig: #? vor ? behandeln.
   %,_,\ im Literal-Text werden via likeEscape() maskiert. */
private static function globToLike(string $glob): string { ... }

public static function search(string $path, string $glob, bool $dirsToo): void
{
    if ($glob === '') { Response::error(400, 'search requires q'); return; }
    $scope = dbPath($path);                    // relativ, ohne führenden '/'
    $like  = self::globToLike($glob);
    $sql = 'SELECT id, path, is_dir, size_bytes, checksum, revision,
                   change_seq, UNIX_TIMESTAMP(modified_at) AS mtime_ts
            FROM files
            WHERE user_id = ? AND deleted_at IS NULL
              AND SUBSTRING_INDEX(path, "/", -1) LIKE ? ESCAPE "\\\\" ';
    $args = [Auth::$user_id, $like];
    if ($scope !== '') {                        // nur unterhalb des Scopes
        $sql   .= 'AND path LIKE ? ESCAPE "\\\\" ';
        $args[] = self::likeEscape($scope) . '/%';
    }
    if (!$dirsToo) { $sql .= 'AND is_dir = 0 '; }
    $sql .= 'ORDER BY path ASC LIMIT 2000';     // Sicherheitskappe
    // fetchAll -> entries[] wie in changes(): path => '/'.$row['path'],
    //   type file|dir, size, md5, mtime, id, revision, change_seq
    // Response::ok(['entries'=>$entries, 'truncated'=> count==2000]);
}
Repo-Memory: PHP 7.4-kompatibel bleiben (kein match, keine enums/union types). Prepared Statements + likeEscape() wie überall sonst. Matching auf dem Basename (SUBSTRING_INDEX(path,'/',-1)), da die Joker per pattern.h-Konvention nur das letzte Pfadsegment betreffen.

Grenze: reine AmigaDOS-Klassen ([abc], (a|b)) übersetzt globToLike nicht 1:1 — für */?/#? (der plattformübergreifende Standard) ist die Abbildung exakt. Das reicht für die Anforderung.

5. amicloud-commander (der aufwändige Teil)

Aktives Panel entscheidet die Quelle: PANEL_CLOUD → cmd_search (Server), PANEL_LOCAL → lokaler Walk (localfs_readdir + pattern_match). Für die lokale Seite kommt der Wildcard-Matcher pattern.h ins Spiel.

Geteilter Kern — core/common/{include/common/search.h,src/search.c} (neu)

typedef struct { char path[1024]; int is_dir; long size, mtime; } SearchHit;
typedef void (*SearchHitFn)(const SearchHit*, void *ud);
/* lokaler rekursiver Walk: localfs_opendir/readdir (Vorlage:
   count_local_tree(), panel.c:135) + pattern_match() auf Basenamen. */
int search_local(const char *root, const char *pattern, SearchHitFn cb, void *ud);

(Cloud-Suche im Commander ruft direkt cmd_search; search_local deckt die lokale Panel-Seite ab. Vorlage-Rekursion existiert in panel.c.)

Ablauf

  • Requester — schöner Such-Dialog: Muster-Eingabe, Scope (aktueller Ordner / ganze Cloud), Checkbox „auch Ordner".
  • Ergebnisfenster — modelos, listet alle Treffer als volle Pfade. Einzelinstanz: wird bei neuer Suche wiederverwendet (neu befüllen + nach vorn), nicht ein zweites Fenster.
  • Gehe zu — Doppelklick/Enter auf einen Treffer: das auslösende Panel springt in den Ordner und markiert die Datei.

  2. CLI/Shell (PC): make -f Makefile.pc für amicloud + amicloud-shell; amicloud search '*.txt' /, in der Shell cd docs + search #?.info (cwd-relativ) und find foo? — Trefferpfade gegen bekannten Baum prüfen.
  3. Commander (Qt): cmake --build build-qt; App starten (/run), F4/Suchbutton → Requester, Muster eingeben, Ergebnisfenster prüfen; Doppelklick auf Treffer → korrektes Panel springt in den Ordner und markiert die Datei; zweite Suche → dasselbe Fenster wird wiederbenutzt; Cloud- und Local-Panel testen.
