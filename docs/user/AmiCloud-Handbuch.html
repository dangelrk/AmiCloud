AmiCloud

Handbuch — eigener Cloud-Speicher für AmigaOS 3.x und PC · Version 1.0 (27.09.2026)

AmiCloud verbindet den Amiga über HTTPS mit einem eigenen AmiCloud-Server. Die Dateien darauf lassen sich per Kommandozeile, in einer interaktiven Shell, mit einem Dateimanager oder als ganz normales Laufwerk CLOUD: benutzen. Kommandozeilenprogramme und Dateimanager gibt es auch für macOS, Linux und Windows. Dieses Handbuch entspricht inhaltlich dem AmigaGuide-Handbuch AmiCloud.guide.

1. Einführung

AmiCloud ist ein selbst betriebener Cloud-Speicher, der für den Amiga gemacht ist. Ein kleiner PHP-Server auf einem Linux-Rechner hält die Dateien, jeder Benutzer hat seinen eigenen Bereich. Alle Programme sprechen den Server ausschließlich über HTTPS an; auf dem Amiga übernehmen das bsdsocket.library und AmiSSL 5, auf dem PC libcurl.

┌────────────────────────┐   HTTPS   ┌──────────────────────────────┐
│ amicloud, -shell,      │◄─────────►│ Apache + PHP                 │
│ cloudsync, Commander   │           │   api.php  REST-API          │
│ (Amiga und PC)         │           │   web.php  Weboberfläche     │
└────────────────────────┘           │ MariaDB (Benutzer, Metadaten)│
┌────────────────────────┐   HTTPS   │ Speicher/<benutzer>/        │
│ CLOUD:-Handler (Amiga) │◄─────────►│                              │
└────────────────────────┘           └──────────────────────────────┘
ProgrammPlattformZweck
amicloudAmiga + PCKommandozeilen-Client, ein Befehl je Aufruf
amicloud-shellAmiga + PCinteraktive Sitzung mit cd, ls, get, put …
cloudsyncAmiga + PCeinmaliger Abgleich lokaler Ordner ↔ Cloud
amicloud-commanderAmiga (MUI) + PC (Qt 6)Dateimanager mit zwei Panels
AmiCloudPrefsAmigaEinstellungs-Editor für amicloud.cfg
amicloud-handler, amicloud-workerAmigaLaufwerk CLOUD: (Handler und Netzwerk-Prozess)

Der Server merkt sich neben dem Dateiinhalt auch Amiga-Eigenschaften: Protection-Bits, Dateikommentare und das Änderungsdatum. Über CLOUD: funktionieren deshalb auch Protect, FileNote und SetDate.

2. Voraussetzungen

WasWofür
AmigaOS 3.x, 68000 oder besseralle Amiga-Programme
TCP/IP-Stack mit bsdsocket.library (Version 4 oder neuer), z. B. Roadshow, AmiTCP, Miamialle Programme außer AmiCloudPrefs
AmiSSL 5 (amisslmaster.library) mit den CA-Zertifikaten der AmiSSL-Installationalle Programme außer AmiCloudPrefs
MUI 3.8 oder neuer (muimaster.library ab Version 19)nur amicloud-commander
ein erreichbarer AmiCloud-Serveralle Programme außer AmiCloudPrefs

Stack muss nicht eingestellt werden: die Programme fordern beim Start selbst 64 KB an, der Handler erhält 16 KB über seinen DOSDriver, der Worker 64 KB beim Start durch den Handler.

Speicher: Der CLOUD:-Handler hält eine geöffnete Datei vollständig im Arbeitsspeicher. Für sehr große Dateien lieber amicloud get/put benutzen, die direkt von und auf die Platte übertragen.

3. Installation mit Install-AmiCloud Amiga

Die Installationsschublade AmiCloud (zum Beispiel aus AmiCloud.lha) enthält:

AmiCloud/
  Install-AmiCloud          Installationsskript
  Uninstall-AmiCloud        Deinstallationsskript
  ReadMe                    Kurzbeschreibung
  LICENSE                   GNU GPL Version 3
  C/                        alle Programme
  Docs/AmiCloud.guide       Handbuch (AmigaGuide)
  Examples/                 amicloud.cfg.example, CLOUD.mountlist
  Storage/DOSDrivers/CLOUD  DOSDriver für CLOUD:

In einer Shell:

CD AmiCloud
Execute Install-AmiCloud

Das Skript fragt nacheinander (Antwort y oder n):

  1. Kommandozeilenprogramme nach C:
  2. amicloud-commander nach SYS:Tools
  3. AmiCloudPrefs nach SYS:Prefs
  4. CLOUD:-Handler nach L: und DEVS:DOSDrivers

Danach legt es ENVARC:amicloud.cfg und ENV:amicloud.cfg aus der Beispieldatei an – aber nur, wenn es sie noch nicht gibt. Eine vorhandene Konfiguration und ein vorhandener DOSDriver DEVS:DOSDrivers/CLOUD werden nie überschrieben. Anschließend bietet das Skript an, AmiCloudPrefs zu starten (dort Server, Benutzer und Passwort eintragen und Speichern wählen) und CLOUD: sofort zu mounten. Ist HELP: zugewiesen, kopiert es das Handbuch nach HELP:AmiCloud.guide.

amicloud list /
Dir CLOUD:

Für die Programme werden keine Icons mitgeliefert. Wer AmiCloudPrefs oder den Commander von der Workbench starten möchte, legt sich ein Icon an.

5. AmiCloud auf dem PC macOS · Linux · Windows

Für den PC gibt es amicloud, amicloud-shell, cloudsync und den Dateimanager amicloud-commander (Qt 6). Sie werden aus den Quellen gebaut (Kapitel 16) und mit make install nach /usr/local/bin installiert (PREFIX/DESTDIR werden unterstützt), oder von Hand aus bin/pc/ kopiert.

Konfiguration: dieselben Schlüssel wie auf dem Amiga (Kapitel 7), die Datei heißt ~/.amicloudrc (Windows-Builds ohne MSYS-Umgebung: amicloud.cfg im aktuellen Verzeichnis). Der Qt-Commander liest ~/.amicloudrc (Windows ohne HOME: %USERPROFILE%\.amicloudrc) und fragt fehlende Angaben in einem Verbindungsdialog ab, speichert sie aber nicht.

cp config-examples/amicloud.cfg.example ~/.amicloudrc
chmod 600 ~/.amicloudrc
amicloud list /

6. Den Server einrichten

Der Server liegt im Quellcode unter server/ und läuft auf Linux mit Apache 2.4, PHP 7.4 oder neuer (Erweiterungen pdo_mysql und fileinfo) und MariaDB/MySQL. HTTPS ist Pflicht: die API lehnt Klartext-HTTP mit 403 ab. Die vollständige Anleitung mit allen Befehlen steht in docs/INSTALL.md; hier die Kurzfassung für amicloud.example.com:

  1. Virtual Host mit DocumentRoot /var/www/amicloud und AllowOverride All anlegen. Der Server gehört an die Wurzel des Hostnamens, weil web.php sich mit /web.php verlinkt.
  2. HTTPS: sudo certbot --apache -d amicloud.example.com
  3. Dateien: sudo cp -r server/. /var/www/amicloud/ – mit Punkt, damit die .htaccess-Dateien mitkommen. Speicherverzeichnis /var/amicloud-storage außerhalb des Web-Verzeichnisses anlegen, beides dem Apache-Benutzer geben.
  4. config.php aus config.php.example kopieren und ausfüllen (Tabelle unten).
  5. Datenbank: sudo mysql < /var/www/amicloud/sql/schema.sql, dann einen DB-Benutzer mit SELECT, INSERT, UPDATE, DELETE auf amicloud.* anlegen. sql/migrate_001.sql bis migrate_003.sql sind nur für ältere Installationen.
  6. Benutzer anlegen: 
    php -r 'echo password_hash("geheim", PASSWORD_BCRYPT), PHP_EOL;'
sudo mysql amicloud -e \
  "INSERT INTO users (username, pass_hash) VALUES ('bob', '\$2y\$10\$...');"
  7. Testen: 
    curl -u bob:geheim "https://amicloud.example.com/api.php?action=status"
AC_SERVER=https://amicloud.example.com AC_USER=bob AC_PASS=geheim \
    sh scripts/test_api.sh
    Weboberfläche: https://amicloud.example.com/web.php
Konstante in config.phpBedeutung
AMICLOUD_TIMEZONEZeitzone aller Zeitangaben der API (bewusst nicht UTC, Standard Europe/Berlin); sollte zu gmt_offset/dst der Amiga-Clients passen
DB_HOST, DB_NAME, DB_USER, DB_PASSDatenbankzugang
STORAGE_PATHabsoluter Pfad des Speicherverzeichnisses, außerhalb des Web-Verzeichnisses; je Benutzer entsteht automatisch ein Unterordner
MAX_UPLOADgrößte Datei in Bytes; post_max_size (und memory_limit) in der php.ini passend wählen
AMICLOUD_ALLOW_HTTPerlaubt Klartext-HTTP – nur für einen lokalen Test mit php -S, nie in Produktion
Hinweis PHP-FPM
Läuft PHP als FPM/CGI, reicht Apache die Basic-Auth-Daten nicht von selbst weiter – jede Anfrage endet dann mit 401. Abhilfe: CGIPassAuth On im <Directory>-Block.

7. Konfiguration: amicloud.cfg

Alle AmiCloud-Programme lesen dieselbe Datei. Jede Zeile hat die Form schluessel=wert, Zeilen mit # am Anfang sind Kommentare.

server=https://amicloud.example.com
user=bob
pass=geheim
#basepath=/
#verify_ssl=1
#debug=T:amicloud.log
#gmt_offset=60
#dst=0
SchlüsselStandardBedeutung
server– (Pflicht)Basis-URL des Servers, ohne /api.php
user / username– (Pflicht)Benutzername
pass / password– (Pflicht)Passwort (steht im Klartext in der Datei)
basepath/Startverzeichnis auf dem Server; Pfade ohne führenden / beziehen sich darauf
verify_ssl11 = Serverzertifikat prüfen, 0 = nicht prüfen (nur zum Testen)
debugleernur CLOUD:-Handler (amicloud-worker): Ziel für ein ausführliches HTTP/TLS-Protokoll, z. B. T:amicloud.log oder CON:0/0/640/200/AmiCloud Debug/CLOSE
gmt_offset0nur Amiga: Abstand der Systemuhr zu UTC in Minuten (MEZ = 60)
dst0nur Amiga: 1 = Sommerzeit, addiert 60 Minuten

gmt_offset und dst werden von amicloud-shell und vom CLOUD:-Handler ausgewertet. Die Amiga-Uhr kennt keine Zeitzone; ohne passende Werte stimmen die Datumsangaben von Dateien nicht mit dem Server überein. Auf dem PC werden beide Werte ignoriert.

ProgrammGesucht wird (erste gefundene Datei gilt)
amicloud, amicloud-shell, cloudsync (Amiga)-c <datei>, sonst ENV:amicloud.cfg, sonst amicloud.cfg im aktuellen Verzeichnis
amicloud, amicloud-shell, cloudsync (PC)-c <datei>, sonst ~/.amicloudrc (Windows ohne MSYS: amicloud.cfg im aktuellen Verzeichnis)
amicloud-commander (MUI)ENV:amicloud.cfg, sonst amicloud.cfg im aktuellen Verzeichnis
amicloud-commander (Qt)~/.amicloudrc, fehlende Angaben per Dialog
amicloud-worker (CLOUD:)nur ENV:amicloud.cfg, einmal beim Start
AmiCloudPrefsENV:amicloud.cfg, sonst ENVARC:amicloud.cfg

ENV: ist nach einem Neustart leer; damit die Einstellungen bleiben, gehört die Datei auch nach ENVARC: – AmiCloudPrefs erledigt das mit Speichern. Kommandozeilenoptionen (-s, -u, -p, -d, -k) gehen den Werten aus der Datei vor.

8. AmiCloudPrefs Amiga

Aufruf: SYS:Prefs/AmiCloudPrefs. Ein GadTools-Fenster mit den Feldern Server, Benutzer, Passwort, Basis-Pfad, Zertifikat prüfen, Debug-Ziel, GMT-Offset (Min) und Sommerzeit – also allen Schlüsseln aus Kapitel 7.

KnopfWirkung
Speichernschreibt ENVARC:amicloud.cfg und ENV:amicloud.cfg (gilt sofort und dauerhaft)
Benutzenschreibt nur ENV:amicloud.cfg (gilt bis zum Neustart)
Abbrechenschreibt nichts

Unterscheiden sich ENV: und ENVARC:, zeigt die Statuszeile einen Hinweis; angezeigt werden dann die Werte aus ENV:. Der CLOUD:-Handler liest die Datei nur einmal beim Start – geänderte Einstellungen wirken dort erst nach einem Neustart.

11. cloudsync – Ordner abgleichen Amiga + PC

cloudsync [Optionen] <lokaler-ordner> <remote-ordner>
OptionBedeutung
-s, -u, -p, -cwie bei amicloud
-kZertifikat nicht prüfen (nur zum Testen)
-nProbelauf: zeigt, was passieren würde, ändert nichts
--helpKurzhilfe

cloudsync gleicht einen lokalen Ordner einmalig in beide Richtungen mit einem Ordner auf dem Server ab und beendet sich dann – kein Hintergrunddienst. So wird entschieden:

  • nur auf einer Seite geändert → wird zur anderen Seite übertragen
  • auf beiden Seiten gleich geändert → nichts zu tun
  • auf beiden Seiten verschieden geändert → Konflikt: die Datei wird übersprungen und gemeldet, nichts wird überschrieben
  • auf einer Seite gelöscht, auf der anderen unverändert → die Löschung wird übertragen

Den Stand des letzten Abgleichs merkt sich cloudsync in der Datei .amicloudsync im lokalen Ordner. Fehlende Ordner werden auf beiden Seiten angelegt (nicht beim Probelauf). Rückgabewert 1, wenn Fehler auftraten, sonst 0.

cloudsync -n Work:Texte /texte      ; erst schauen
cloudsync Work:Texte /texte         ; dann abgleichen

12. amicloud-commander – Dateimanager

Ein Dateimanager mit zwei Panels nebeneinander. Jedes Panel zeigt über seinen Umschalter entweder lokale Dateien (Local) oder die Cloud (Cloud). Das zuletzt angeklickte Panel ist das aktive.

MUI-Fassung Amiga

Aufruf: amicloud-commander [-v] (braucht MUI 3.8). Server und Zugangsdaten kommen aus ENV:amicloud.cfg (sonst amicloud.cfg im aktuellen Verzeichnis); fehlt dort server, user oder pass, meldet der Commander das und beendet sich. Beim Start zeigt links das aktuelle Verzeichnis, rechts der Basis-Pfad in der Cloud.

Taste/KnopfAktion
F2Neu laden
F3Info zum gewählten Eintrag
F4Suchen: Muster (* ? #?), rekursiv ab dem Pfad des aktiven Panels; Treffer in eigenem Fenster, Doppelklick oder „Gehe zu“ springt hin
F5Kopieren ins andere Panel (Mehrfachauswahl möglich)
F6Verschieben des gewählten Eintrags ins andere Panel – nur zwischen Local und Cloud, mit Rückfrage
F7Verzeichnis anlegen
F8Löschen des gewählten Eintrags, mit Rückfrage; Verzeichnisse in der Cloud samt Inhalt, lokale nur, wenn sie leer sind
F10Beenden
Menü ProjektÜber AmiCloud Commander… (Amiga-?), Prüfsumme anzeigen (Amiga-M, MD5 der Auswahl), Umbenennen (Amiga-R), Suchen… (Amiga-S), Beenden (Amiga-Q)

Der Commander gibt normalerweise nichts auf der Konsole aus. Zur Fehlersuche: -v beim Start aus der Shell, oder beim Start von der Workbench das Tooltype DEBUG im Icon. Die MUI-Fassung ist auf echter Hardware noch wenig erprobt und meldet sich als „0.1 (unverified)“.

Qt-Fassung PC

Aufruf: amicloud-commander [-v|--verbose]. Liest ~/.amicloudrc; fehlen Angaben, fragt ein Verbindungsdialog danach (ohne zu speichern). Gleiche Funktionstasten F2–F10 (zusätzlich Tab wechselt das Panel, Entf löscht, Esc beendet). Unterschiede:

  • F6 verschiebt zwischen Local und Cloud (mit Rückfrage) und benennt um, wenn beide Panels dieselbe Quelle zeigen.
  • F4 fragt zusätzlich nach dem Suchbereich (aktueller Ordner oder alles) und ob Ordner mitgesucht werden.
  • Menüs: Ansicht (Versteckte Dateien ausblenden), Extras (Prüfsumme anzeigen, Suchen…), Hilfe (Über AmiCloud Commander…).

Gemeinsam

  • Existiert eine Datei beim Kopieren schon, zeigt eine Abfrage Größe, Datum und MD5 beider Seiten; zur Wahl stehen Überschreiben, Überspringen, Alle überschreiben, Alle überspringen und Abbruch.
  • Laufende Übertragungen zeigen einen Fortschrittsbalken mit Abbrechen-Knopf.
  • Kopieren von Cloud zu Cloud ist nicht möglich.

13. CLOUD:-Handler – die Cloud als Laufwerk Amiga

Der Handler macht den eigenen Cloud-Bereich zu einem AmigaDOS-Laufwerk CLOUD:; auf der Workbench erscheint es als Datenträger AmiCloud. Installation: amicloud-handler und amicloud-worker nach L:, der DOSDriver CLOUD nach DEVS:DOSDrivers/, dazu eine vollständige ENV:amicloud.cfg (Kapitel 3).

Mount CLOUD:          ; sofort (sonst beim nächsten Systemstart automatisch)
Dir CLOUD:
MakeDir CLOUD:Texte
Copy DH0:bericht.txt CLOUD:Texte/
Copy CLOUD:Texte/bericht.txt RAM:
Rename CLOUD:Texte/bericht.txt CLOUD:Texte/alt.txt
Protect CLOUD:Texte/alt.txt +p
FileNote CLOUD:Texte/alt.txt "Mein Kommentar"
SetDate CLOUD:Texte/alt.txt today
Delete CLOUD:Texte ALL

Was funktioniert: Lesen, Schreiben, Anlegen, Löschen und Umbenennen von Dateien und Verzeichnissen, Protection-Bits, Dateikommentare (bis 79 Zeichen), Datum setzen, Workbench-Fenster auf AmiCloud.

So arbeitet er: Der Handler selbst (amicloud-handler) beantwortet nur die DOS-Pakete. Die gesamte Netzwerkarbeit erledigt ein zweiter Prozess, amicloud-worker, den der Handler beim Mounten aus L: startet (er wartet bis zu 30 Sekunden darauf). Der Worker liest ENV:amicloud.cfg einmal beim Start und baut die Netzverbindung erst bei der ersten Anfrage auf – das Mounten beim Booten klappt deshalb auch, wenn der TCP/IP-Stack später startet. Verzeichnisinhalte werden 10 Sekunden zwischengespeichert. Eine geöffnete Datei wird ganz in den Speicher geladen und beim Schließen hochgeladen, wenn sie geändert wurde.

Grenzen

  • Kein Abmelden: CLOUD: bleibt bis zum Neustart gemountet. Neue Programmversionen und geänderte Einstellungen wirken erst danach.
  • Anfragen laufen nacheinander; eine langsame Übertragung hält andere Zugriffe auf CLOUD: so lange auf.
  • Antwortet der Worker 60 Sekunden lang nicht, schlägt die Anfrage fehl, und alle weiteren Zugriffe scheitern sofort bis zum Neustart – das Laufwerk friert aber nicht ein.
  • Ein nicht leeres Verzeichnis lässt sich nicht direkt löschen; Delete … ALL funktioniert (DOS löscht Eintrag für Eintrag).
  • Info CLOUD: zeigt eine feste, plausible Kapazität, keine echte Belegung.
  • Ein Laufwerk, kein Diskwechsel, kein Formatieren, kein Umbenennen des Datenträgers.
  • Große Dateien brauchen entsprechend viel freien Speicher.
  • Eine Datei namens debuglog im Wurzelverzeichnis der Cloud ist über CLOUD: nicht erreichbar (der Name ist für die Diagnose reserviert, siehe Fehlersuche).

14. Fehlersuche

ProblemAbhilfe
„server URL required“, „username required“, „password required“Konfiguration fehlt oder ist unvollständig: ENV:amicloud.cfg bzw. ~/.amicloudrc prüfen, auf dem Amiga AmiCloudPrefs starten und Speichern wählen.
„network initialisation failed“TCP/IP-Stack läuft nicht (bsdsocket.library fehlt) oder AmiSSL 5 ist nicht installiert. Mit -v zeigen amicloud und amicloud-shell auf dem Amiga, wo es scheitert.
ZertifikatsfehlerUhrzeit des Amiga prüfen (ein falsches Datum macht Zertifikate ungültig) sowie die AmiSSL-Installation samt CA-Zertifikaten. Nur zum Testen: -k bzw. verify_ssl=0.
Anmeldung abgelehnt (401)Benutzername/Passwort prüfen; serverseitig bei PHP-FPM CGIPassAuth On (Kapitel 6).
Datum von Dateien stimmt nichtgmt_offset/dst passend zur Amiga-Uhr setzen und mit AMICLOUD_TIMEZONE des Servers vergleichen.
Mount CLOUD: schlägt fehlLiegt amicloud-worker in L:? Der Handler wartet bis zu 30 Sekunden auf den Worker.
CLOUD: reagiert nicht wie erwartetIn ENV:amicloud.cfg z. B. debug=T:amicloud.log eintragen, neu starten, Fehler auslösen und das Protokoll ansehen – der Worker protokolliert jeden Schritt vom Öffnen der Bibliotheken bis zur HTTP-Anfrage. Zusätzlich zeigt Type CLOUD:debuglog das Protokoll der Handler-Seite.

15. Deinstallation

Amiga: in der Installationsschublade Execute Uninstall-AmiCloud. Das Skript löscht die Programme aus C:, SYS:Tools, SYS:Prefs und L:, den DOSDriver und HELP:AmiCloud.guide; die Konfiguration nur nach Rückfrage. Ein gemountetes CLOUD: verschwindet erst mit dem nächsten Neustart. Von Hand:

Delete C:amicloud C:amicloud-shell C:cloudsync
Delete SYS:Tools/amicloud-commander SYS:Prefs/AmiCloudPrefs
Delete L:amicloud-handler L:amicloud-worker
Delete DEVS:DOSDrivers/CLOUD HELP:AmiCloud.guide
Delete ENV:amicloud.cfg ENVARC:amicloud.cfg     ; nur wenn gewünscht

PC: amicloud, amicloud-shell, cloudsync, amicloud-commander aus dem Installationsverzeichnis und ggf. ~/.amicloudrc löschen.

16. Bauen aus den Quellen

Die gemeinsamen Bibliotheken stecken im Projekt AmiCloudCore, das als Git-Submodul core/ eingebunden ist. Alle Einzelheiten stehen in docs/BUILD.md.

git clone --recurse-submodules https://github.com/dangelrk/AmiCloud.git
cd AmiCloud
make pc                   # PC: amicloud, amicloud-shell, cloudsync (libcurl)
make qt                   # PC: Qt-Commander (Qt 6, CMake)
export VBCC=/pfad/zu/vbcc
make amiga                # Amiga-Programme per vbcc -> bin/amiga/
make dist-amiga           # Installationsschublade build/dist/AmiCloud/

Nativ auf dem Amiga (vbcc, AmiSSL-, Roadshow- und MUI-SDK) im Projektverzeichnis Execute Build-Amiga; die SDK-Pfade stehen oben im Skript (AMISSL_INC, NET_INC, MUI_INC) oder werden über die Zuweisungen AmiSSL:, NetInclude:, MUI: gesetzt. Das Skript ist auf echter Hardware noch ungetestet.

17. API-Kurzreferenz und Sicherheit

Vollständige Referenz: docs/api/API.md. Basis-URL https://amicloud.example.com/api.php, HTTP Basic Auth bei jeder Anfrage. Antworten: {"status":"ok",…} bzw. {"status":"error","code":N,"message":"…"}; download liefert die Rohdaten.

ActionBedeutung
statusVersion, Serverzeit, Änderungszähler
listVerzeichnis auflisten inkl. Protection-Bits, Kommentar, MD5
downloadDatei herunterladen (auch Teilbereiche mit offset/length)
uploadDatei hochladen (POST-Rumpf, optional md5=, 422 bei Abweichung)
deletelöschen (recursive=1 für nicht leere Verzeichnisse)
infoMetadaten einer Datei oder eines Verzeichnisses
mkdir, renameVerzeichnis anlegen, umbenennen/verschieben
setcomment, setprotect, setdateDateikommentar, Protection-Bits, Änderungsdatum setzen
searchNamen rekursiv suchen (* ? #?), höchstens 2000 Treffer
changesÄnderungen seit einem Zählerstand
  • HTTPS erzwungen (außer im lokalen Testmodus AMICLOUD_ALLOW_HTTP), Zertifikatsprüfung in den Clients standardmäßig an
  • Passwörter nur als bcrypt-Hash in der Datenbank
  • Speicherverzeichnis außerhalb des Web-Verzeichnisses, jeder Benutzer in eigenem Unterordner; Pfade mit .. und Sonderzeichen werden abgelehnt
  • .htaccess sperrt config.php und includes/
  • Weboberfläche: Sitzungs-Cookie nur über HTTPS, SameSite=Strict, CSRF-Token in allen Formularen
  • Client-seitig steht das Passwort im Klartext in amicloud.cfg bzw. ~/.amicloudrc – Datei entsprechend schützen
