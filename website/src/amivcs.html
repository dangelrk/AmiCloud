AmiVCS

Version {{v:amivcs}}Amiga · Browser · Mac und PC folgen AmiVCS auf Aminet

Versionsverwaltung für den Amiga und den PC: Commits, Branches und Merges, dazu ein eigener Server mit Weboberfläche.

Experimentell: Mit Hilfe von Claude (KI-Assistent von Anthropic) entwickelt, in erster Linie für den Eigengebrauch des Autors. Probiere es zuerst mit Kopien deiner Daten aus.

Installieren

  1. Lade AmiVCS.lha von Aminet, packe es aus und starte Install-AmiVCS. Du brauchst AmigaOS 3.x und mindestens einen 68020; für den Server-Betrieb außerdem einen TCP/IP-Stack und AmiSSL 5, für die Oberfläche MUI. {{fig:vc-install|Der Installer von AmiVCS.}}
  2. Wenn du einen Server nutzt, trage ihn in AMIVCSPrefs ein. Der Benutzername ist zugleich der Autor deiner Commits. {{fig:vc-prefs|AMIVCSPrefs auf der Workbench.}}

Die Fassung für Mac und PC folgt mit der Veröffentlichung auf GitHub. Die Einzelheiten stehen im Handbuch.

Das erste Repository

Öffne eine Shell im Projektordner. AmiVCS arbeitet immer im Wurzelverzeichnis des Repositorys.

amivcs init
amivcs add -A
amivcs commit -m "Erster Stand"
amivcs log

Für einen Versuch legst du einen Branch an und führst ihn später wieder zusammen:

amivcs branch experiment
amivcs switch experiment
amivcs add -A
amivcs commit -m "Experiment"
amivcs switch main
amivcs merge experiment

Die Oberfläche

Dasselbe geht mit amivcs-gui. Links stehen die geänderten Dateien, rechts das, was in den nächsten Commit kommt, darunter die Historie aller Branches.

{{fig:vc-mui|amivcs-gui auf dem Amiga.}} {{fig:vc-qt-haupt|amivcs-gui in der kommenden Fassung für den Mac, hier mit gezeichnetem Commit-Graphen.}}
  1. Merke Dateien mit Stage oder alle mit Stage All vor. {{fig:vc-qt-staged|Beide Dateien sind für den Commit vorgemerkt.}}
  2. Schreibe eine Nachricht und klicke auf Commit.
  3. Branches legst du über das Menü Repository an, wechselst sie dort und führst sie zusammen. Clone, Push und Pull stehen unter Remote.

Mit dem Server arbeiten

Ein Server hält deine Repositories zentral vor, damit Amiga und PC denselben Stand haben. Der erste Push legt das Repository auf dem Server an:

amivcs push projekt-x     ; auf dem ersten Rechner
amivcs clone projekt-x    ; auf dem zweiten Rechner
amivcs pull               ; Stand der Gegenseite holen
amivcs push               ; eigene Commits senden

Der Server liegt dem Archiv als Schublade Server bei, die Einrichtung steht im Handbuch.

Die Weboberfläche

Im Browser siehst du Code, Historie und Änderungen. Neue Commits entstehen nur auf dem Client, im Browser änderst du lediglich die Einstellungen eines Repositorys.

  1. Meine Repositories zeigt alles, was dir gehört. Über die Einstellungen eines Repositorys machst du es öffentlich oder privat. {{fig:vc-web-repos|Die eigenen Repositories.}}
  2. Code zeigt die Dateien je Branch und das README. {{fig:vc-web-code|Dateibaum und README.}}
  3. Historie zeigt alle Commits mit Graph. {{fig:vc-web-history|Die Historie mit Commit-Graph.}}
  4. Ein Klick auf einen Commit zeigt, was sich Zeile für Zeile geändert hat. {{fig:vc-web-diff|Ein Commit mit seinen Änderungen.}}

Trage auf deinen Geräten nicht dein Kontopasswort ein, sondern ein App-Passwort. Du legst es in der Weboberfläche unter Einstellungen an und kannst es einzeln widerrufen.
